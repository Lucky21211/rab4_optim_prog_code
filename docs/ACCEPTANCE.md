# Проверки и контракты

## Совместимость

Веб-страницы: `/` → `/dashboard`, `/dashboard`, `/iss`, `/osdr`, `/page/{slug}`. Формы JWST и AstronomyAPI, карта, графики, CMS и просмотр raw OSDR сохранены. Маршрут `/iss` восстановлен: раньше ссылка принудительно перенаправляла в dashboard.

Веб API: `/api/iss/last`, `/api/iss/trend`, `/api/jwst/feed`, `/api/astro/events`. Rust API: `/health`, `/last`, `/fetch`, `/iss/trend`, `/osdr/sync`, `/osdr/list`, `/space/:src/latest`, `/space/refresh`, `/space/summary`. Внутренние `/jwst/feed` и `/astro/events` добавлены для централизации внешних клиентов.

Сохраняются успешные поля last, trend, OSDR, gallery и summary. `points` добавлено в trend без удаления старых полей, поскольку графики уже ожидали этот массив. Astronomy возвращает исходные ответы в `data[].raw` и нормализованные `events` для таблицы; это исправление неработавшей интеграции.

## Ошибки

Для JSON API Rust и `/api/*` Laravel ошибки приложения, валидации, БД и внешних поставщиков возвращаются как HTTP 200:

```json
{"ok":false,"error":{"code":"UPSTREAM_403","message":"External provider rejected request","trace_id":"UUID"}}
```

Поля успешных ответов не оборачиваются в новый объект. Клиент обязан проверять `ok === false`, а не только response.ok. Коды ошибок не кэшируются. trace_id связывает HTTP-ответ и JSON-лог.

Правило HTTP 200 применяется к JSON API, а не к HTML-навигации, статическим файлам и защитным ответам веб-форм. Например, неизвестная CMS-страница сохраняет 404, а POST /upload без CSRF-токена — 419. Иначе теряется защита и семантика страниц.

## Автоматические сценарии

| Проверка | Ожидаемый результат |
|---|---|
| Два /fetch | Снимки МКС, корректные coordinates и trend.points |
| Два /osdr/sync | Один бизнес-объект OSD-1 после upsert |
| /space/refresh и /space/summary | Все пять поставщиков, прежние ключи, ограниченный размер space_cache |
| Страницы и формы | HTTP 200, четыре интерфейса без JS-ошибок |
| GalleryProvider fake | Реализация источника меняется через DI без изменений контроллера |
| 403 | Одна попытка, HTTP 200 и ok=false/UPSTREAM_403 |
| 429 затем 200 | Ограниченный повтор с Retry-After, успешный ответ |
| Неверный limit/lat/program | VALIDATION_ERROR без запросов к поставщику |
| 10 одновременных одинаковых gallery GET | Один внешний запрос благодаря Cache-Aside и single-flight lock |
| Одновременный /fetch | Нет наложения job одного source; JOB_BUSY для занятых |
| Повтор CSV import | Одна строка по бизнес-ключу |
| CMS XSS | Скрипты и опасные атрибуты удалены, безопасная разметка сохранена |
| POST upload без CSRF | HTTP 419 |
| down/up без -v | Число сохранённых ISS-записей не изменилось |

## Производительность

В summary число SQL round trips уменьшено с 7 до 3: одна выборка пяти источников, последняя ISS-запись и count OSDR. Это свойство кода; абсолютное время ответа следует измерять на одинаковых данных. Для одного заполненного gallery cache десять повторных запросов не вызывают внешнее API. Проверка считает обращения к mock, а не делает вывод по ненадёжному времени Postman.

`space_cache` хранит одну текущую запись на source с upsert; ISS остаётся историческим append-only журналом, поскольку тренд использует несколько наблюдений. В OSDR исправлен predicate частичного уникального индекса в ON CONFLICT. Индекс inserted_at DESC/id DESC поддерживает ограниченный список.

Сроки кэша: ISS/OSDR 10 секунд, JWST/events 120, CMS 60; параметры меняются через env. Кэш frontend отделён от основной PostgreSQL через Redis. При записи CMS вручную устаревшее содержимое может оставаться до TTL; для немедленного обновления требуется `php artisan cache:clear`.
